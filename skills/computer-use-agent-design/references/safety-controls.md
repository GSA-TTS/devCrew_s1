# Safety controls and rollout stages

Used for Part 6 (Safety limits: Control, Status, Design note), one row per control below, and Part 7 (Findings and rollout). Controls 1 to 11 are the mandatory production components.

## Controls (Control column, with what the Design note must cover)

1. Environment pool and isolation: one disposable browser context or desktop per task, never a profile reused across tenants, never the model host or a personal desktop; the model worker separate from the executor. Low-risk browser-only work may use a non-root container with a hardened browser, read-only base image, task-specific writable profile, seccomp or equivalent, cgroups and deny-by-default egress; untrusted native desktop applications or multi-tenant workloads use a microVM or full VM. Block host home directories, cloud metadata, runtime sockets, SSH agents, developer credentials, shared clipboards, USB, host audio and camera, and local-network discovery. Pin image, OS, browser, driver, applications, fonts, locale, viewport, DPI, zoom and scaling.
2. Automation and input adapter: translates model actions into the automation runtime or OS input; the model has no direct access to browser, desktop, vault, filesystem or network.
3. Display and screenshot pipeline: headed mode in a virtual display when visual parity, native dialogs, extensions or takeover matter; fixed display size (a session that resizes invalidates all coordinates); lossless images for small text and precise coordinates; a hash over the exact bytes sent to the model; redaction of passwords, tokens, payment and health data, personal messages, unrelated windows and notifications before model exposure and storage, and no click on a redacted screenshot unless the target geometry is still valid.
4. Policy and action gateway: validates every proposed action, blocks forbidden destinations and shortcuts, requires approvals and enforces budgets in code; holds a kill switch that stops new actions, revokes credentials, freezes or ends sessions and quarantines output.
5. Credential vault and session broker: user-delegated OAuth, passkeys or short-lived task tokens rather than static passwords; vault outside the model and the environment; a pre-authenticated session scoped to tenant, origin, account, task class and expiry, with unrelated cookies stripped. Cookies, local storage, profiles, CSRF tokens, passkeys, QR-code screenshots and remote-view links are secrets. Revoke sessions at task end; on suspected hijacking stop, revoke, preserve evidence and rebuild from a clean image.
6. Network egress proxy: deny by default; enforce schemes, origins, ports, methods, redirects, DNS, private-address blocking, upload and download policy, bytes and duration; revalidate every redirect and pop-up. An allowed domain is not enough where users can host content, upload files or create share links on it.
7. Task and checkpoint store: goal, constraints, completion criteria, environment ID and version, current URL or application, open targets, artifacts, approvals, last verified checkpoint, remaining budget and a summary of completed work, kept outside the environment; stale approvals revoked on resume.
8. Recording, evidence and replay store: redacted screenshots, action records kept separate from video, state hashes, downloads and verification outcomes, under an explicit retention policy; replay never repeats production writes.
9. Human-takeover interface: viewing through an authenticated, tenant-scoped gateway; remote-control links scoped to one session with short expiry; strong user authentication for takeover; no concurrent viewers unless explicitly authorized.
10. Observability: traces, metrics, redacted logs and security events that correlate task, environment, session, observation, screenshot, grounding, action, wait, verification, recovery, approval, takeover, artifact and cleanup.
11. Evaluation harness: resettable sites or VMs, task fixtures, ground-truth postconditions, fault injection, prompt-injection pages and recorded flows, with thresholds set before viewing candidate results.
12. Untrusted content handling: trusted instructions come only from system policy, authenticated user intent, deterministic workflow state and approved configuration. Page text, screenshots, alt text, accessibility labels, images, QR codes, ads, notifications, downloads, error messages and documents are data: they cannot change policy, expand scope, approve an action, request a secret, authorize a destination, disable recording, raise a budget or redefine success. A screenshot-only agent is not immune. Stop at once on a provider safety block, detected injection, unexpected credential request, forbidden destination, sandbox violation or action outside the task, without asking the model for a workaround; never downgrade a provider-required confirmation.
13. Data-loss prevention: checks on outgoing text, uploads, URLs, form destinations and downloads, with data classes bound to destination classes and byte limits; a denied upload may not reappear as pasted text, an email, a share link, a URL query or a screenshot. A logged-in screen is not proof that an action is authorized: every policy decision keeps the user, workload, tenant, purpose, destination and account.
14. Authority, terms and privacy: the account owner's authorization, the site's terms, acceptable-use policy, rate limits and prohibited automation recorded before automating; no evading blocks, rotating identities, fake accounts, paywall bypass, or accepting terms, consent or attestations for the user without explicit authority. A lawful purpose and retention policy exist before capture; capture the smallest region at the lowest cadence the task allows; evaluate workplace-monitoring rules when people can watch employee screens.

## Rollout stages (Part 7)

The sequence is: synthetic or self-hosted sites, then read-only canaries, then reversible actions with approval, and only later higher-consequence workflows. While any of controls 1 to 11 is missing, consequential computer use is not deployed: the affected task class stays synthetic, read-only or disabled until the control exists.
